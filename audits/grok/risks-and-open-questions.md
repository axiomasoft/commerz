# Риски, открытые вопросы, расхождения

Формат: «Нужно обсудить:» — решение за владельцем; рядом наша рекомендация и цена ошибки.

## 1. Открытые вопросы

**1. Нужно обсудить: SaaS на общих таблицах или БД на арендатора?**
Рекомендация — без `tenant_id`, изоляция соединением (legacy-platform ADR-004). Если планируется мультиарендный SaaS на одной
схеме — решить **до первой миграции**: `tenant_id` придётся добавить в каждый UNIQUE, FK, индекс, кэш-ключ и очередь.
Добавить позже = переписать все ограничения.

**2. Нужно обсудить: Commerz — самостоятельный пакет или Flex-модуль L1 поверх legacy-platform?**
Рекомендация — самостоятельный (как Chatom/Vaulter/AzGuard), мост `commerz-legacy-platform` для custom-fields, outbox, прав,
мультиаккаунтности. Вариант «L1 legacy-platform» даёт готовые tenancy/outbox/поля, но запрещает установку без legacy-platform и навязывает
префиксы/миграции legacy-platform. Критерий: будет ли хоть один проект с Commerz без legacy-platform.

**3. Нужно обсудить: только Laravel 13 + PHP 8.4 + PostgreSQL ≥ 16?**
Рекомендация — да (так у legacy-platform, `dev-doctrine.md:176`). MySQL отнимет `EXCLUDE`, частичные индексы, `NULLS NOT DISTINCT`,
транзакционный DDL и `jsonb`-операторы — ровно то, на чём держатся инварианты. Поддержка Laravel 12 — только если есть
конкретный проект.

**4. Нужно обсудить: весовые и дробные товары.**
Рекомендация — целые числа в базовой единице (г, мл, мм) + шаг продажи на варианте (`sell_step = 50` г).
«0,35 кг» = 350 г. Если нужен ввод «1,5 м ткани» без смены единицы — всё равно целые мм. Риск: товары с
непредсказуемым фактическим весом (мясо «≈1 кг», цена по факту) — нужна поправка строки при сборке
(`fulfilled_quantity` ≠ `quantity`) и доплата/возврат. В v1 не делаем; подтвердить, что не нужно.

**5. Нужно обсудить: один префикс `cmz_` или префикс на модуль.**
Рекомендация — один настраиваемый `cmz_` + существительное модуля (`cmz_stock_levels`, `cmz_coupons`). Владение
таблицей видно по существительному и проверяется архитектурным тестом. Префиксы на модуль (`ctg_`, `inv_`…) — по
образцу legacy-platform, но там это разные продукты; у одного семейства пакетов это 7 префиксов без выигрыша.

**6. Нужно обсудить: когда резервировать остаток.**
Рекомендация — при размещении заказа (дефолт), опция `OnCheckoutStart` с TTL для дропов. Резерв «при добавлении в
корзину» не предлагаем. Подтвердить для POS: там резерв и списание — одна операция (заказ сразу `fulfilled`).

**7. Нужно обсудить: последовательное сложение скидок.**
Рекомендация — внутри стадии каждая следующая акция считается от уже сниженной цены (10 % + 5 % = 14,5 %).
Альтернатива — от исходной (Shopify: 15 %). Это видимое покупателю поведение — выбрать один раз и не менять.
`ExclusiveSelection::Best` (выбрать лучшую из эксклюзивных) — v1.1, если попросят.

**8. Нужно обсудить: значения атрибутов по каналу.**
Рекомендация — в v1 нет: одно значение на товар/вариант, локализация — картой локалей. Каналам отличаются
публикация, цена, наличие — не характеристики. Если нужны разные описания для маркетплейса — отдельный тип атрибута
`channel_text` (плагин), без fallback-цепочки в ядре.

**9. Нужно обсудить: подарочные сертификаты и бонусные баллы.**
Рекомендация — **не акции**: это платёжное средство/обязательство (баланс, срок, частичное списание, бухучёт).
Отдельный пакет `commerz-giftcards` как `PaymentGateway` + свой журнал. Если смешать с купонами — сломаются возвраты
и налоговая база.

**10. Нужно обсудить: цены с НДС или без.**
Рекомендация — флаг на канале `prices_include_tax` (РФ/ЕС B2C — да, США/B2B — нет), налог выделяется из цены
стадией `tax`. Влияет на округление: выделенный НДС считается построчно, расхождение в копейку возможно и
документируется. Решить до формата цен в прайс-листах.

**11. Нужно обсудить: лимиты акций расходуются при размещении неоплаченного заказа.**
Плюс — нет claim-фазы. Минус — злоупотребление: создать 100 неоплаченных заказов и «съесть» лимит. Защита:
`payment_due_at` (по умолчанию 30 мин) + автоотмена + лимит неоплаченных заказов на покупателя. Если этого мало —
расход при оплате с риском «лимит кончился после оплаты» (возврат денег). Выбрать политику.

**12. Нужно обсудить: 6 пакетов с первого дня или один пакет с модулями.**
Рекомендация — монорепо с 6 пакетами и split-публикацией (как Chatom/AzGuard). Если команда из 1–2 человек и все
проекты ставят полный набор — один пакет с теми же границами модулей под архитектурным тестом; разрезать позже.

## 2. Технические риски

| Риск | Где | Митигация |
|---|---|---|
| Горячий SKU: все резервы ждут блокировку одной строки уровня | `cmz_stock_levels` | транзакция размещения короткая (сеть вне её), `lock_timeout 3s`; при необходимости — шардирование остатка на N «вёдер» уровня (не v1) |
| Взаимоблокировки при многострочных заказах | резерв | сортировка по `stock_level_id`, фиксированный порядок: склад → купоны → акции → покупатель (проверено 8 процессами) |
| Рост `cmz_stock_movements` и `cmz_order_events` | журналы | BRIN по времени, партиционирование по месяцу при > 50 млн строк |
| Расхождение `reserved` и суммы броней | склад | сверка `commerz:inventory:reconcile` (отчёт, не автоисправление) |
| Расхождение документа атрибутов и проекции | каталог | запись в одной транзакции; `commerz:catalog:reindex` пересобирает проекцию из документа |
| Удалён плагин типа/условия | атрибуты, акции | статус `unsupported`, fail-closed, данные не трогаются |
| Изменение конфига плагина | акции | `config_version` + `upgrade()`; невалидный конфиг → `unsupported`, не исключение в корзине |
| Повторная доставка webhook платежа | sales | уникальный `(gateway, external_id)` в `cmz_payment_transactions` |
| Изменение валюты магазина | деньги | запрещено при наличии заказов; новая валюта = новый канал |
| Laravel/Eloquent-магия в `Internal` | весь код | обработчики пишут через Query Builder + строгий `Row`; Eloquent — только для чтения в админке (`commerz-filament`) |

| Документ | Их позиция | Наша | Почему |
|---|---|---|---|
| design-hypotheses §2 | упаковка A/B/C открыта | 6 пакетов + плагин купонов | критерий «реальная установка без соседа» |

| logical-schema-candidate §5 | `stock_resources`, `dimension_key`, allocations, transitions | levels + movements + reservations | 3 таблицы покрывают v1; лоты/серийники — рядом с уровнем, ключ не меняется |
| logical-schema-candidate | `command_receipts` | естественные ключи идемпотентности | ключ брони/погашения уже уникален; проверено повтором и конкуренцией |
| logical-schema-candidate §6 | `coupon_claims`, `promotion_quota_resources/claims`, claim groups | расход в транзакции заказа | неоплаченный заказ и есть удержание; prototype E5–E7 |

| attribute-storage-options (вариант G) | асинхронная проекция | синхронная | фасеты не должны врать после сохранения; объём проекции мал (только фильтруемые) |
| logical-schema-candidate / design-hypotheses | fallback-цепочка и значения по каналу | один уровень, без каналов | предсказуемость; §1.8 |
| ecosystem-conventions | legacy-platform/Agentools не исследовались | legacy-platform — главный источник конвенций | раскладка STR-006, словарь суффиксов, DATA-004, ADR-003/004 |
| design-hypotheses (replace model) | подмена моделей — «спорный escape hatch» | закрываем: без подмены | модели в `Internal`; их же довод — last-wins без диагностики |

| ChatGPT architecture-appendix | `BIGINT` PK + `public_id` | UUIDv7 | экосистема (legacy-platform ADR-003, Chatom), ID до INSERT, слияние БД; одна колонка вместо двух |
| ChatGPT architecture-appendix §6.3 | typed EAV с атомами/группами | JSONB-документ + проекция | карточка за 1 строку; фильтры по проекции; оси — реляционно |
| logical-schema-candidate §12 | критерий отказа: «потребитель с 6 полями создаёт десятки definitions» | не срабатывает | 6 сложных свойств Unbox = 6 строк `cmz_attributes` (+ при нужде тип-плагин) |

**Согласны:** оплата ≠ физическое движение (design-hypotheses §10); без поиска глобального оптимума скидок (§9);
формула доступности наборов (ChatGPT §8.5); префикс `cmz_` и детерминированное сокращение имён (ecosystem-conventions); PostgreSQL-first; снимок заказа не зависит от каталога.
