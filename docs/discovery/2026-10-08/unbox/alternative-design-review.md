# Unbox: альтернативы для небольшого набора сложных свойств

2026-10-08. Независимое статическое чтение migrations, Catalog models и текущих Sales Forms; CLAUDE.md учтён. Приложение, БД и тесты не запускались. Unbox не изменялся. Победитель не выбран.

«Не более шести» пока неоднозначно: шесть **свойств на товар**, шесть **типов значений** или шесть **осей вариантов** дают разные ограничения. Даже шесть осей с десятью значениями каждая означают миллион комбинаций. 

Все ссылки на код ниже ведут к сохранённым в Commerz снимкам. В подписи указаны исходный файл и номер строки Unbox; внутри снимка сохранены полные пути и исходная нумерация.

## Термины и опорные факты

- **Definition:** свойство «цвет» с именем, областью магазина и правилами. **Type:** семантика значения и валидатор; SQL string/decimal и UI control — самостоятельные характеристики. В Unbox `type`, `control`, `unit` уже разнесены: [2025_10_19_185330_create_cat_properties_table.php:18](schema-sources.md).
- **Option value:** конкретное значение справочника, например «красный», со стабильным ID. Unbox хранит text/integer/decimal columns: [2025_10_19_185334_create_cat_property_values_table.php:22](schema-sources.md). Это словарь значений свойства.
- **Variant axis:** роль свойства в различении SKU/предложений. «Цвет» может быть осью, «страна происхождения» — описанием. Текущий [OffersForm.php:289](workflows-sources.md) строит комбинации переданных свойств; отдельный флаг роли в прочитанных таблицах не найден.
- ProductProperty задаёт связь свойства с товаром и `available_codes`; предложение выбирает PropertyValue через pivot. Unique `(offer, value)` исключает повтор того же значения, но сам по себе допускает два разных цвета: [2025_10_19_185427_create_cat_product_offer_property_values_table.php:20](schema-sources.md).

## Пять вариантов

| Вариант | Когда оправдан | Цена гибкости и проверка |
|---|---|---|
| Фиксированные колонки | Несколько стабильных, одинаковых во всех проектах полей | Явные типы, простые constraints и индексы. Новое поле требует migration; перенос отраслевых колонок в общий пакет связывает его с конкретным каталогом. |
| Дочерние предметные сущности | Свойство имеет структуру и собственные правила: состав, диапазон, совместимость | Чёткие FK и доменные методы. Больше таблиц/joins; расширение требует кода. Пригодно для нескольких сложных типов, даже при малом числе свойств. |
| JSON + registry типов | Типы добавляются приложениями, значения обычно читаются целиком | Компактная запись, независимый UI adapter. Нужны schema version, стабильный type key, миграции значений и стратегия индексов; validation вне БД нельзя считать SQL-гарантией. |
| Typed EAV | Пользователь определяет свойства, нужен поиск по числовым/датным значениям | Типизированные колонки или таблицы по storage type. Требуются constraints, scope uniqueness, multi-value semantics и проверка joins; для шести неизменных полей может быть лишним. |
| Общие option dictionaries + явные назначения | Цвета/размеры и другие переиспользуемые конечные множества | Стабильный option ID, label отдельно, разрешённое подмножество на товаре, FK. Неестественно для произвольного текста/числа; общая правка затрагивает много товаров. Ближе всего к текущему Unbox, но не обязана обслуживать все свойства. |

Варианты допускают композицию: справочник для осей, предметная сущность для состава, JSON для редкого описательного поля. Выбор зависит также от частоты изменения типов, поиска и идентичности SKU.

## Пять сценариев выбора

1. **Описание против оси:** цвет × размер создают шесть продаваемых комбинаций; материал и сертификат их не умножают. Переименование label сохраняет ID предложения, цену и остаток.
2. **Сложное значение:** масса 1,250 кг, диапазон 10–20 мм и состав с суммой долей 100%. Проверить round-trip без float-потерь, нормализацию единиц и диапазонный поиск.
3. **Общий словарь:** два магазина выбирают разные подмножества цветов. Изменение названия/кода и удаление option не должны молча уничтожать варианты. В текущем [PropertiesForm.php:489](workflows-sources.md) values удаляются и создаются заново, а pivot FK использует cascade: статически виден риск потери связей.
4. **Целостность выбора:** подставить значение чужого свойства/магазина, два значения одной оси и дубликат комбинации из второго запроса. Проверить именно пару property→value и область допустимости; простые [OffersForm.php:39](workflows-sources.md) не выражают эти отношения.
5. **Эволюция и масштаб:** сменить тип свойства, выключить его plugin, отфильтровать каталог по трём свойствам и попытаться сгенерировать 10⁶ комбинаций. Сравнить стоимость migration/query, поведение исторических заказов и ограничение генерации. 

Эти сценарии предложены для будущей проверки, а не выполнены. Окончательный выбор зависит от уточнения смысла «шести» и реальных примеров сложных свойств.
